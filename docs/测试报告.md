## 二、典型问题详情

### P0-1：Grounding 千分位误判

- **现象**：报告「8月份总销售额为135,015元，珍珠奶茶是销售最好的商品」数值正确，却返回 `verified=false`；caveat 显示 `'8月份总销售额' 中的数值 135 未在步骤 1 结果中出现`。
- **根因**：数值抽取未先去千分位逗号，`135,015` 被拆成 `135`、`21,984` 被拆成 `21`。
- **修复**：抽取前统一归一化（去千分位/货币符号，支持 `13.5万`、`3.2亿` 等单位），整数/小数分别建比对键；回归用例覆盖 `135,015 / 1,234,567.89 / ¥13,5015 / 13.5万`。
- **回归**：`tests/test_grounding.py`。

### P0-2：「这个月」月份语义漂移

- **现象**：问「这个月卖得怎么样」，返回 138,033（实为 7 月），8 月真实值 135,015。
- **根因**：Planner/Analyst 对「这个月」解析不稳定，未显式绑定数据中最新完整月份。
- **修复**：Planner 显式解析时间范围（默认最新完整月份），报告头标注「本次分析月份：2026-08」，无法确定时追问不猜测。
- **回归**：`scripts/regression.py` 黄金用例断言报告包含 `135015`。

### P1-2：沙箱终止语义

- **现象**：`while True: pass` 进程被杀，返回 `error/rc=-9`，无法区分「墙钟超时」与「资源超限」。
- **修复**：子进程内 `RLIMIT_CPU` 软限=墙钟（SIGXCPU）+ 硬限 +5s（SIGKILL）双限，返回体保留 `exit_code / signal / elapsed`，测试断言可精确匹配。
- **回归**：沙箱用例 + 冒烟 15/15。

### P2-2：趋势分析（唯一一个修复后复测仍不达标、需二轮方案的问题）

- **现象**：问「有没有卖得越来越差、该少进货的商品」，报告未识别真实衰减商品（芋泥波波），且只分析 8 月单月（伪趋势）。
- **根因**：纯 LLM 生成分析步骤，趋势意图与时间范围不稳定；单月环比被当作「趋势」。
- **修复（确定性链路替代 LLM 自由发挥）**：意图识别（`is_trend_question`）→ 强制 `product_trend` 步骤 → 显著性三分类过滤（阈值以真实数据标定）→ Top 下降提取 → Reporter 聚焦。
- **回归**：`tests/test_trend_intent.py`、`tests/test_product_trend.py` + `scripts/regression.py` 步骤级断言（代码含 `product_trend`、无单月过滤正则特征）。
